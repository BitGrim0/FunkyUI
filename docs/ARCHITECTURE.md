# FunkyUI — архитектура

Документ описывает, как устроена библиотека внутри. Требования — в `REQUIREMENTS.md`.

## Файлы

```
FunkyUI.sln

include/FunkyUI.h               единственный публичный заголовок
src/
  Base.h / Base.cpp             память, Array, HashMap, Arena, хэши, математика, UTF-8 → UTF-16
  Internal.h                    интерфейсы модулей, GpuShape / GpuGlyph, UiImpl
  Host.cpp                      окно-оверлей: слежение за целью, ввод, click-through, пейсинг кадров

  Text.cpp                      DirectWrite: шрифты, раскладка, растеризация глифов в атлас, кэши
  Ui.cpp                        UiImpl: жизненный цикл, кадр, ID, ввод, панели, Transition, сборка кадра

```

## Кадр

```
BeginFrame
  Host.WaitForFrame        ждём waitable swapchain'а (после Present) или DwmFlush (кадр пропущен)
  Host.Update              сообщения окна, позиция/размер/z-order цели, курсор
  оверлей: массивы кадра меняются местами с массивами прошлого (для сравнения в EndFrame)
  Frame.Reset, очистка Shapes/Runs/Clips/Points, OpenContainers = [Root]
  ввод → DIPs, фронты кнопки
  HoveredPanel = верхняя панель под курсором по прямоугольникам ПРОШЛОГО кадра
код клиента
  панели, контейнеры, контролы → Place() → Interact() → Draw*() → GpuShape / GpuGlyph в текущий слой
EndFrame
  PointerOverUi → Host.SetClickThrough(!PointerOverUi)
  BuildFrame: батчи в порядке отрисовки (фон → панели по z-order → foreground), с opacity панелей
  Renderer.RestoreDevice   устройство потеряно → пересоздаётся, атлас загружается заново целиком
  кадр побайтно равен прошлому (уже показанному) и атлас не менялся → Present пропускается
  иначе Renderer.UpdateAtlas + Renderer.Render
  GC (раз в 8 кадров): панели, состояния контейнеров и Transition, не встречавшиеся 8+ кадров, удаляются;
      таблица, ставшая в 8+ раз больше содержимого, пересобирается по размеру
  Text.EndFrame            конец жизни раскладок кадра, освобождение неиспользованных; сброс заполненного атласа — только здесь
```

В режиме встраивания шагов Host, RestoreDevice и сравнения с прошлым кадром нет — см. «Режим встраивания (embedded)».

## Координаты и DPI

Всё API работает в DIPs (1 DIP = 1 px при 96 DPI), начало координат — левый верхний угол клиентской
области цели. Host отдаёт физические пиксели и `DpiScale`; UiImpl переводит курсор в DIPs.
Шейдер переводит DIPs в пиксели через `DpiScale` из constant buffer, сглаживание считается в пикселях.

## ID и состояние

- `Id = HashCombine(id родительского контейнера, key)`.
- Ключ: явный `Key` из props; иначе у Button — хэш текста, у CheckBox/Slider — адрес привязанной
  переменной (`Key::FromPointer`), у Label/безымянных контейнеров — позиционный индекс
  (счётчик `PositionalIndex` родителя растёт только для элементов без явного ключа).
- Строковый литерал в `Key` хэшируется при компиляции (`consteval`), в бинарник не попадает.
- Постоянное состояние лежит в `HashMap` по id: `PanelState`, `ContainerState`, `TransitionState`.
  У каждого `LastFrame`; не встречавшиеся 8 кадров удаляются в EndFrame.
- Указатели на значения `HashMap` нельзя держать через вызовы, которые могут вставить в ту же карту.

## Layout

Immediate-mode с памятью прошлого кадра, как договаривались:

- **Листья** (Label, Button, ...) знают свой желаемый размер сразу (текст меряется через кэш),
  поэтому размещаются без задержки: `Place(desired, spec)` возвращает итоговый прямоугольник.
- **Контейнер** в `BeginContainer` получает позицию и размер по поперечной оси сразу, а размер по
  главной оси — из прошлого кадра (`ContainerState.ContentSize`). В `EndContainer` родительский курсор
  сдвигается на РЕАЛЬНЫЙ размер этого кадра, поэтому вложенные стеки не «прыгают».
- **Panel** — вертикальный стек с Padding. Положение зависит от размера (Anchor), размер берётся с
  прошлого кадра. Первый кадр появления панели — невидимый проход измерения (без отрисовки и ввода),
  затем панель плавно проявляется через Transition прозрачности.
- **Stack**: `Orientation`, `Spacing`. В вертикальном стеке ребёнок по умолчанию растягивается по
  ширине (`HorizontalAlignment::Stretch`), в горизонтальном — по высоте строки.
- **Grid**: до 8 колонок `Auto` / `Px` / `Star`, строки всегда Auto, заполнение по строкам.
  Ширина Auto-колонки и высота строки — максимумы прошлого кадра (до 64 строк), Star делит остаток.
- `Width/Height = 0` — автоматически; `Min*/Max*` ограничивают; `Margin` снаружи элемента.

## Ввод и click-through

- Кнопки мыши приходят сообщениями окна (с учётом быстрых кликов внутри одного кадра), курсор
  опрашивается `GetCursorPos` каждый кадр — так окно успевает перестать быть сквозным до клика.
- Вне интерактивного режима UI не реагирует на мышь, окно всегда сквозное.
- В интерактивном режиме `PointerOverUi = курсор над видимой панелью || над виджетом вне панелей ||
  идёт захват (ActiveId)`. В EndFrame окно становится сквозным, только если `PointerOverUi == false`.
- Виджет «hovered», если: интерактивный режим, он включён, курсор в его прямоугольнике и в текущем
  клипе, его панель == `HoveredPanel` (для фона — под курсором нет панели), и нет чужого ActiveId.
- Нажатие на hovered-виджете → `ActiveId = id` (+ `SetPointerCapture`). Отпускание: `Clicked`,
  если курсор всё ещё над виджетом; `ActiveId = 0`.
- Нажатие на панель: в `EndScope` панели, если за этот кадр никто из детей не взял ActiveId и
  нажатие пришлось на эту панель → панель становится Active (захват до отпускания: цель не получает
  половину клика). Если она `Movable`, то двигается за курсором, сохраняя точку захвата.
  Любое нажатие на панель поднимает её наверх z-order. Панель не выходит за пределы окна.
- Клавиатура (TextBox) — этап 2: фокус забирается только на время ввода.

## Анимации

`Transition(ключ, target, duration)`: при смене цели значение начинает движение от текущего к новому
с ease-out (`1 - (1 - t)^3`) — как в Avalonia/WPF: смена цели посреди движения продолжает от текущего значения.
Первый вызов сразу возвращает target. Время — настоящее (dt кадра), шаг не чаще раза за кадр. Цвета смешиваются
в линейном premultiplied пространстве. В покое значение — ровно target (узнаётся по битам цели), поэтому
законченный переход стоит один поиск и одно сравнение, без конвертаций цвета. Состояние (48 байт) живёт в
`Transitions` и удаляется вместе с неиспользуемыми виджетами.
Тайминги встроенных контролов — константы в Controls.cpp, подобранные вручную.

## Рендер

- Каждый примитив — один instanced quad; VS строит его из `SV_VertexID` (triangle strip, 4 вершины,
  `DrawInstanced(4, count)`), input layout нет. Два вида примитивов, как в GPUI (Zed): у каждого свой structured
  buffer и свои шейдеры, чтобы текст не платил ни за 96-байтную фигуру, ни за SDF-шейдер:
  - `GpuShape` (96 байт, `Shape.hlsl`) — PS считает SDF: скруглённый прямоугольник (радиус на каждый угол),
    полилиния, дуга с круглыми концами, треугольник (сглаживаются только внешние рёбра);
  - `GpuGlyph` (32 байта, `Glyph.hlsl`) — прямоугольник в DIPs, углы в текселях атласа (16 бит на координату),
    цвет, индекс клипа; PS — выборка покрытия из атласа × цвет.
- Градиент у текста: у глифа один цвет, CPU берёт его из градиента в центре глифа (смешивание как в шейдере —
  premultiplied, в линейном пространстве; концы переводятся в линейное пространство один раз на строку). Горизонтальный градиент идёт по строке от глифа к глифу; внутри глифа
  цвет не меняется, поэтому вертикальный градиент в одной строке даёт один цвет на строку.
- Порядок отрисовки. Ui пишет фигуры и глифы в два массива в порядке вызовов, run'ы — диапазоны одного вида
  в одном слое. BuildFrame подаёт run'ы в порядке отрисовки (фон → панели по z-order → foreground, внутри слоя —
  в порядке вызовов) и режет их на «уровни»: уровень рисует все свои фигуры, потом все свои глифы. Глиф уезжает
  после фигур, поданных позже него в его уровне, — это верно, пока они с ним не пересекаются; фигура,
  пересекающая прямоугольник текста текущего уровня (подсветка поверх подписи, панель поверх текста другой
  панели), начинает следующий уровень. Касание считается пересечением. Панель из подписей, слайдеров и кнопок
  обычно — один уровень, т. е. два draw call'а, а непересекающиеся панели делят их. Текстов в уровне не больше
  32 (граница числа проверок на фигуру).
- `DrawBatch` = вид + диапазон его буфера + opacity слоя; соседние батчи одного вида, продолжающие друг друга,
  сливаются. GPU читает массивы Ui как есть (никакого копирования и переупорядочивания кадра): батчи
  указывают на диапазоны. Opacity панели (Opacity × fade-in) — константа батча, шейдеры умножают на неё
  premultiplied-результат (фигура гаснет целиком, вместе с обводкой).
- Константы на батч (первый инстанс — `SV_InstanceID` его не включает — и opacity) пишутся `Map(WRITE_DISCARD)`;
  шейдеры переключаются только при смене вида. SRV t0–t4 (фигуры, клипы, атлас, точки, глифы) привязаны к обоим
  стадиям один раз за кадр.
- Буферы инстансов, точек и клипов — DYNAMIC, растут удвоением, каждый кадр перезаписываются целиком через
  `Map(WRITE_DISCARD)` (драйвер выдаёт свежую память, пока GPU читает прошлый кадр — без ожидания).
- Полилиния (и Безье, разбитая на хорды) — один инстанс на каждые ≤ 64 сегмента: вершины лежат в
  structured buffer точек кадра, PS берёт расстояние до ближайшего сегмента. Поэтому тело, AA и glow
  каждого пикселя смешиваются один раз, а стыки круглые (перекрытие только на стыке инстансов).
- `p` в PS — центр пикселя из `SV_Position`, а не интерполированная позиция: он побитово одинаков во
  всех инстансах, и шов веера треугольников (`DrawPolygon`) достаётся ровно одному из них.
- Покрытие = `saturate(0.5 - d_px)`. Внутренняя обводка, внешнее свечение (glow) — в том же
  инстансе; заливка и обводка считаются только там, где покрытие > 0, обводка — только при толщине > 0,
  glow — только снаружи (настоящие ветки в DXBC). Концы градиента VS переводит в линейное пространство один раз
  на инстанс.
- Тень под фигурой без градиента (прямоугольник или круг) — в инстансе самой фигуры (`FlagShadow`: смещение и σ в
  P2, цвет в Fill1): PS кладёт её под тело (`тело + тень × (1 − тело.a)`, premultiplied «over» ассоциативен —
  то же, что нарисовать её раньше, с точностью до 1 LSB), пиксели под фигурой смешиваются один раз. Тень под
  градиентной фигурой или без фигуры — отдельный инстанс с `Softness > 0` (размытый силуэт) перед ней.
- Быстрый путь больших заливок: для сплошного скруглённого прямоугольника VS выдаёт точную внутреннюю
  область — снова скруглённый прямоугольник (фигура, сжатая на обводку + 1 px, радиус r − это), где покрытие
  заведомо 1, обводки и glow нет. Там PS сразу возвращает premultiplied-цвет из VS, не читая фигуру и не считая
  SDF. У размытого силуэта область — где его покрытие полное (3,5σ внутрь, ошибка 2·10⁻⁴); у фигуры с тенью —
  пересечение областей фигуры и тени, цвет — фигура поверх тени. Круг получает ~76 % своего квада (было ~46 %).
- Дуга рисуется квадом по её фактическим экстремумам (концы и пройденные направления осей), а не полного круга.
- Клип-прямоугольник читается в VS (индекс в самой фигуре / глифе), PS только сравнивает; смена клипа не
  разбивает батч.
- Смешивание в sRGB (UNORM RTV), вывод premultiplied alpha (`ONE, INV_SRC_ALPHA`) — как ждёт
  DirectComposition. Градиенты и Transition цветов интерполируются в линейном пространстве.
- Пропуск кадра (только оверлей) точный: кадр побайтно сравнивается с прошлым — viewport и DpiScale, батчи
  (порядок слоёв, диапазоны, opacity панелей), клипы, точки, фигуры, глифы. Прошлый кадр не копируется: в
  BeginFrame массивы меняются местами с массивами прошлого кадра, и новый кадр пишется в освободившиеся буферы.
  Изменившийся кадр обычно отличается в первых байтах, и сравнение сразу заканчивается; неизменный кадр — это
  один проход по памяти без хэширования. Всё, что не было показано (окно скрыто, Present не удался), ставит
  ForceRedraw, так что «равен прошлому» всегда значит «уже на экране»; изменение атласа, resize и восстановление
  устройства — тоже. Встраивание не сравнивает.
- Swapchain: `CreateSwapChainForComposition`, FLIP_SEQUENTIAL, B8G8R8A8_UNORM, premultiplied,
  2 буфера, `FRAME_LATENCY_WAITABLE_OBJECT`, `SetMaximumFrameLatency(1)`. Начальный сигнал waitable
  забирается сразу при создании, поэтому каждое ожидание в `WaitForFrame` парно одному Present; Present(1, 0)
  после этого ожидания только ставит кадр в очередь. DirectComposition коммитится один раз при создании.
- Потеря устройства (обновление драйвера, TDR, смена GPU), только оверлей: `RestoreDevice` в каждом EndFrame
  проверяет `GetDeviceRemovedReason`, пересоздаёт всё (не чаще раза в 60 кадров при неудаче), и Ui
  просит у Text полную перезаливку атласа.
- Шейдеры собираются `FxCompile` (SM 5.0) в заголовки с байт-кодом, `/Qstrip_reflect /Qstrip_debug`.
- Профайлер фаз EndFrame — только при сборке с `FUNKY_PROFILE` (по умолчанию выключен, кода нет вовсе):
  тики QueryPerformanceCounter последнего кадра — Build (BuildFrame), Upload (атлас и буферы),
  Draw (состояние и draw call'ы), Present. Читается внутренним `Funky::GetFrameProfile(ui)` из `Internal.h`
  после EndFrame; define нужен и библиотеке, и читателю.

## Текст

- Раскладка (`Text.Layout`) идёт одним из двух путей с одинаковым результатом. `MeasureText` (`Text.Measure`)
  проходит тот же простой путь без квадов и растеризации глифов; сложный текст меряет по кэшированной раскладке
  (простой путь при этом не повторяется).
  - **Простой текст** — латиница, греческий, кириллица, цифры, пунктуация, `\n`, `\t`, если у шрифта стиля
    есть все глифы. Это один глиф на символ: для шрифта (семейство, вес, курсив) один раз строится таблица
    «символ → индекс глифа, advance» (`GetGlyphIndices`, `GetDesignGlyphMetrics`), кернинг пары один раз
    берётся у shaping'а DirectWrite (GPOS или kern) и запоминается. Раскладка строится заново на каждый
    вызов — без кэша и хэша строки — прямо в память кадра (место на глиф на байт, потом хвост отдаётся назад).
    Квад глифа — это первые 24 байта `GpuGlyph` (прямоугольник относительно начала строки и тексели атласа),
    а `TextLayout` несёт объединение квадов (`Ink`), так что рисование — одно копирование со сдвигом.
    `DrawString` однотонного простого текста пишет глифы сразу в инстансы кадра (без промежуточной раскладки).
    Встроенные контролы и заголовок панели раскладывают свой текст один раз: размер берут из раскладки и её же
    рисуют (внутренние `UiImpl::LayoutText` / `DrawLayout`). Последний использованный шрифт (семейство, вес,
    курсив, размер в пикселях) запоминается до конца кадра, поэтому подряд идущий текст одного стиля не ищет
    его в таблицах.
    Память кадра сбрасывается в `Text.EndFrame`, а если кадр занял меньше 1/8 её (после всплеска текста) —
    освобождается и растёт заново. Меняющийся каждый кадр текст стоит столько же, сколько статичный. Пара,
    которую shaping меняет сильнее кернинга (лигатура, контекстная форма), отправляет строку на второй путь.
  - **Остальное** (другие письменности, комбинируемые знаки, глифа нет в шрифте, управляющие символы, переносы
    строк кроме `\n`: CR, CRLF, VT, FF, NEL, U+2028, U+2029 — как у DirectWrite) —
    `IDWriteTextAnalyzer`: `AnalyzeScript`, `AnalyzeBidi`, системный fallback `IDWriteFontFallback::MapCharacters`,
    `GetGlyphs` + `GetGlyphPlacements` по run'ам, run'ы строки в визуальном порядке (правило L2 bidi).
    Результат кэшируется по хэшу (текст, шрифт, размер, вес, курсив, DpiScale), сам текст не хранится.
    Кэш двухпоколенный, как в Zed GPUI: попадание в `Previous` переносит раскладку в `Current`, в
    `Text.EndFrame` всё, что осталось в `Previous`, освобождается, и поколения меняются местами. Раскладка,
    не использованная за кадр, исчезает — разовые строки память не копят. EndFrame обходит карту поколения
    целиком, поэтому карта, ставшая в 8+ раз больше своего содержимого (после всплеска разовых строк),
    освобождается и растёт заново по размеру.
  - Оба пути повторяют раскладку DirectWrite: natural advances в DIPs, высота строки по метрикам шрифта (line
    gap над ascent), перо и baseline округляются до физического пикселя, табуляция — к следующей позиции,
    кратной 4 × размер шрифта.
- Каждый глиф растеризуется `IDWriteFactory2::CreateGlyphRunAnalysis` (grayscale) в физических пикселях и
  кладётся в атлас R8G8 (канал G — distance field, этап 2). Простой текст берёт место глифа в атласе из
  таблицы шрифта на размер в пикселях (живёт по той же двухпоколенной схеме).
- Координаты глифов в `GpuGlyph` — в текселях (шейдер умножает на `AtlasTexelSize`). Атлас растёт
  1024 → 2048 → 4096 с сохранением текселей, поэтому уже выданные за кадр глифы остаются верными.
  Заполненный атлас 4096 сбрасывается целиком (глифы и раскладки) только в `Text.EndFrame`; до конца
  кадра новые глифы пустые.

## Правила no-CRT (для всего кода библиотеки)

- Никаких функций CRT: `malloc`, `memcpy`, `sinf`, `printf`, ... — только помощники из `Base.h`.
  Компилятор может сам вставить вызовы `memcpy`/`memset`/`memmove`: их даёт клиент (CRT или свои).
- Никаких STL-контейнеров, `std::format`, iostream, исключений, RTTI.
  Из STL — только заголовочное: `<span>`, `<string_view>`, `<bit>`, `<type_traits>`, `<new>`.
- Никаких глобальных объектов с конструкторами и function-local static с динамической инициализацией.
- Стековые массивы не больше ~2 КБ (иначе `__chkstk`).
- Никаких строковых литералов в release-коде: `Key("...")` хэшируется при компиляции,
  `FK_ASSERT` есть только в debug. Имена системных DLL — через `#pragma comment(lib, ...)`
  (это директива линкеру, в итоговый бинарник строкой не попадает).
- Проект собирается с `/GS-`, `/GR-`, без исключений и с `/Zl` (библиотека не навязывает CRT), с
  `_ALLOW_RUNTIME_LIBRARY_MISMATCH` и `_ALLOW_ITERATOR_DEBUG_LEVEL_MISMATCH` (заголовки STL не ставят
  `FAILIFMISMATCH` на RuntimeLibrary и уровень отладки итераторов), в Debug — `_ITERATOR_DEBUG_LEVEL=0`.

## Проверка в облаке

Сборка проверяется clang-cl 20 (MSVC STL 17.14, Windows SDK 10.0.26100) и настоящим `fxc.exe`
через wine. Демо линкуется без CRT (`/NODEFAULTLIB`) — это проверяет совместимость с no-CRT.
Что при этом делает клиент без CRT:
- `/NODEFAULTLIB` отбрасывает и `#pragma comment(lib)` библиотеки, поэтому системные .lib
  (user32, dwmapi, d3d11, dxgi, dcomp, dwrite) перечисляются в линковке явно.
- Debug: `_ITERATOR_DEBUG_LEVEL=0` и у библиотеки, и у клиента — иначе проверки MSVC STL в
  `std::span`/`std::string_view` зовут `_CrtDbgReport`. При `/Od` строковый литерал → `string_view`
  зовёт `strlen`: его клиент даёт сам, как `memcpy`.
Запуск и визуальная проверка — на Windows.

## Режим встраивания (embedded)

`Ui::CreateEmbedded` создаёт UI без окна и swapchain'а на устройстве D3D11 клиента: Host не создаётся, Renderer берёт
ссылку на устройство (AddRef) и его immediate context и создаёт на нём только свои шейдеры, состояния, буферы и атлас.
Клиент каждый кадр вызывает `SetRenderTarget(rtv, w, h, scale)` и (для ввода) `SetPointer(pos, down)`, затем
`BeginFrame`/`EndFrame`. Остальной Renderer (загрузка буферов, атлас, отрисовка батчей) общий с оверлеем.

- `SetRenderTarget` задаёт цель ближайшего `EndFrame`: размер в физических пикселях, viewport в DIPs = размер / scale.
  Ссылка на RTV держится только до конца этого `EndFrame`: между кадрами библиотека не держит back buffer, и
  `ResizeBuffers` клиента работает. RTV — UNORM (не `_SRGB`): вывод в sRGB с premultiplied alpha, как в оверлее.
- `SetPointer` — курсор в физических пикселях цели и левая кнопка. Фронты считаются в самом вызове: при вызове раз
  в кадр нажатие и отпускание внутри одного кадра теряются, при вызове на каждое событие мыши — нет. Интерактивный
  режим — `SetInteractive`, как в оверлее; click-through и захвата мыши нет (нет окна), ввод клиент направляет сам
  по `IsPointerOver()`.
- `BeginFrame` не ждёт и не качает сообщения, dt — по `QueryPerformanceCounter`, всегда возвращает true.
- `EndFrame` собирает кадр как обычно, заливает атлас, если нужно, и рисует поверх содержимого цели без очистки и
  Present. Пропуска кадров нет: цель клиента перерисовывается каждый кадр. Пустой кадр контекст не трогает.
- Состояние контекста, которое меняет отрисовка, сохраняется перед ней и восстанавливается после (как в
  `imgui_impl_dx11.cpp`): render targets и DSV, blend state (+ blend factor, sample mask), rasterizer state, viewports,
  input layout, topology, VS и PS (+ class instances) с их t0–t4, s0, b0. GS/HS/DS на время отрисовки снимаются
  и потом возвращаются. Не меняются и поэтому не сохраняются: vertex/index buffers (input layout нет), scissor rects
  (scissor test выключен), depth-stencil state (DSV на время отрисовки не привязан, тесты глубины и трафарета выключены).
  Render targets восстанавливаются первыми (иначе D3D снял бы восстановленные SRV того же ресурса) и только до
  последнего занятого слота (UAV в слотах после него остаются). Сохранённое состояние лежит в Renderer (class instances
  не помещаются на стек).
- Потерю устройства библиотека не обрабатывает — устройство принадлежит клиенту: он пересоздаёт устройство и UI
  (`Destroy` + `CreateEmbedded`).

Этот режим используется бенчмарком Throughput (рендер в offscreen-текстуру без Present) и будет основой встраивания
в чужой swapchain.
