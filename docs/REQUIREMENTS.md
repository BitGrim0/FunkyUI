# FunkyUI — требования

Библиотека UI для оверлеев поверх других приложений: инспекторы, редакторы параметров,
информационные панели. Immediate-mode API в духе Dear ImGui, но с нормальным layout,
встроенными анимациями и современным рендером.

## 1. Принципы

- **Минимализм.** Никакого лишнего и устаревшего. Архитектура простая, но гибкая, без overengineering.
- **Скорость за счёт архитектуры**, а не микрооптимизаций. Код простой и читаемый;
  оптимизируем только то, что видно в профайлере. Никаких хитрых трюков ради мелкого прироста.
- **Числовых целей (строк кода, миллисекунд) нет.**
- **Красиво по умолчанию**: тёмный игровой стиль, плавные анимации без усилий со стороны клиента.
- **Легко писать свои контролы**: встроенные контролы используют только публичный API.

## 2. Платформа и сборка

| Пункт | Решение |
|---|---|
| ОС | Windows 10+, x64 |
| Язык | C++23, стиль имён PascalCase, без исключений, без RTTI |
| Сборка | MSBuild, `.vcxproj` (StaticLibrary), `PlatformToolset = ClangCl` (llvm-msvc). Параметры LLVM в проекте не задаются |
| Подключение | ProjectReference на `.vcxproj`; клиенту нужен один публичный заголовок `FunkyUI.h` |
| Шейдеры | HLSL компилируется при сборке через MSBuild `FxCompile` (fxc, SM 5.0) с `/Qstrip_reflect /Qstrip_debug`, байт-код встраивается в `.lib` |
| Зависимости | Только системные библиотеки Windows: d3d11, dxgi, dcomp, dwrite, windowscodecs (WIC), user32, dwmapi. Сторонних библиотек нет, `d3dcompiler_47.dll` не нужна |
| CRT | Библиотека совместима с no-CRT сборкой клиента: не использует функции CRT и STL-компоненты, требующие runtime (контейнеры с аллокацией, `std::format`, iostream, исключения), нет глобальных конструкторов и `atexit`. Из STL — только заголовочные вещи без runtime (`<span>`, `<string_view>`, `<bit>`, `<type_traits>`, `<concepts>`). Память — через аллокатор, который может задать клиент (по умолчанию `HeapAlloc`). Выбор CRT остаётся за клиентом |

## 3. Окно-оверлей (хост)

- Собственное прозрачное окно поверх окна целевого приложения.
- Цель всегда в режиме **borderless**. Эксклюзивный fullscreen не поддерживается.
- Окно следит за клиентской областью цели: точные размеры через `GetClientRect`/`ClientToScreen`
  (или DWM-границы), без подогнанных вручную коэффициентов.
- Z-order: окно ставится сразу над целью, а не topmost поверх всего.
- DirectComposition + flip-model swapchain, premultiplied alpha, `MaximumFrameLatency = 1`,
  ожидание через frame latency waitable object.
- Per-Monitor DPI Aware v2.
- Если кадр не изменился, Present не выполняется.
- Имя класса окна задаёт клиент.

## 4. Цикл кадра

Как в ImGui: клиент сам управляет циклом, скрытых потоков в библиотеке нет.

```cpp
ui.BeginFrame();
// ... панели и контролы ...
ui.EndFrame();
```

## 5. Ввод

- `SetInteractive(bool)` включает режим меню, клиент вызывает его по своему хоткею.
- Вне режима меню окно полностью сквозное: всё видно, все клики уходят в цель.
- В режиме меню, как в ImGui: курсор над элементом UI — клик обрабатывает UI; над пустым местом —
  клик уходит в цель. Библиотека каждый кадр сама переключает `WS_EX_TRANSPARENT`.
- Клавиатурный фокус забирается у цели **только пока активен TextBox** и возвращается
  после Enter, Esc или клика мимо.
- Запросы состояния: `IsPointerOver()` (курсор над UI или идёт перетаскивание),
  `IsKeyboardFocused()` (активно поле ввода).

## 6. Архитектура UI

- **Гибрид**: immediate-mode API, внутри лёгкая память виджетов между кадрами
  (размеры с прошлого кадра для layout, состояния анимаций). Клиент ничего не хранит.
- **Главного окна нет**: все панели равноправны. Меню — это панель, которую клиент рисует,
  когда меню открыто.
- Панель: `Anchor`, `Margin`, `Movable`, `Title`, опционально `Position` (указатель на переменную клиента).
  Перетаскивание работает только в режиме меню. Позиция запоминается до конца сессии
  и не выходит за пределы экрана.
- Скоупы через RAII (`if (auto p = ui.Panel(...))`), без пар `Begin`/`End` и стеков `Push`/`Pop`.
- Параметры через designated initializers.

## 7. Примитивы

- Линии, полилинии, кривые Безье, треугольники, прямоугольники (в т. ч. скруглённые),
  круги, дуги, выпуклые многоугольники, текст, картинки.
- Эффекты: glow, обводка, градиент, тень (смещение, размытие, цвет).
- Рендер: каждая фигура — один instanced quad, форма и сглаживание считаются в пиксельном шейдере (SDF).
  Полилинии и кривые — один quad на участок до 64 сегментов (расстояние до ближайшего сегмента считается в шейдере,
  поэтому стыки не перекрываются). Минимум draw call'ов на кадр. Тесселяции на CPU нет.
- Произвольные вогнутые фигуры с заливкой — позже, если понадобятся.

## 8. Текст

- DirectWrite: системные шрифты, fallback для кириллицы и эмодзи.
- Атлас глифов с двумя каналами: покрытие (чёткий обычный текст) и distance field (glow, обводка, тень).
- Эффекты текста: glow, обводка, тень (смещение, размытие, цвет).
- На вход — UTF-8 `std::string_view` во время выполнения.
- Кэш раскладок по хэшу строки: хранит индексы глифов, копии текста не хранит.

## 9. Картинки

- Загрузка через WIC (PNG, JPG, BMP) или готовый `ID3D11ShaderResourceView` от клиента.

## 10. Layout

- `Margin`, `Padding`, `HorizontalAlignment`/`VerticalAlignment` (Start, Center, End, Stretch),
  `Width`, `Height`, `MinWidth`/`MaxWidth`, `MinHeight`/`MaxHeight`.
- `Stack`: направление, `Gap`.
- `Grid`: колонки и строки `Auto` / `Px(n)` / `Star(n)`. На нём же строятся таблицы.

## 11. Контролы

Panel, Label, Button, CheckBox, Slider, Drag (float, int, векторы), TextBox, ComboBox,
ColorPicker, Tabs, Image.

Table с произвольным содержимым пока не делаем (табличную раскладку даёт Grid).

- Свойства в духе Avalonia: у каждого контрола своя структура только с уместными полями
  (`Background`, `Foreground`, `BorderBrush`, `BorderThickness`, `CornerRadius`, `Padding`,
  `FontSize`, `FontWeight`, `Opacity`, `Glow`, ...). Brush — цвет или градиент.
- Значения по умолчанию — вручную настроенный тёмный игровой стиль.
- Цвета hover и pressed по умолчанию выводятся из `Background`; при желании задаются явно
  (`HoverBackground`, `PressedBackground`).
- **Глобальной темы (Theme) нет.** Нужен другой вид — параметры контрола или свой контрол.

## 12. Анимации

- `Transition(widget, target, duration)`: значение плавно (ease-out) идёт к цели за заданное время;
  текущее значение хранит библиотека. Работает для чисел, векторов и цветов
  (цвета интерполируются в линейном пространстве, без «грязных» промежуточных оттенков).
- Встроенные контролы анимируют смену цвета при наведении и нажатии, переключение состояний,
  открытие и закрытие всплывающих элементов.
- ComboBox: список раскрывается и закрывается анимацией (высота + прозрачность), подсветка
  пункта плавно переезжает между пунктами. Всплывающие элементы рисуются поверх всех панелей.
- Тайминги встроенных контролов подобраны вручную для каждого контрола и снаружи не настраиваются.

## 13. ID виджетов

- ID = хэш подписи + ID родителя, вычисляется во время выполнения.
- Скрытые ключи: `Key("...")` — `consteval`-хэш, самой строки в бинарнике нет.
- `std::source_location` не используется (вшивает пути к файлам).

## 14. Строки в бинарнике

Библиотека в release не добавляет собственных строковых литералов:

- шейдеры — только байт-код, без reflection;
- без input layout (вершины читаются по `SV_VertexID`), значит без имён семантик;
- без assert'ов, логов и текстов ошибок в release, только коды ошибок;
- имя класса окна и шрифты задаёт клиент;
- видимый текст всегда приходит от клиента во время выполнения.

## 15. Не входит в библиотеку

- Эксклюзивный fullscreen, внедрение в чужие процессы и хуки.
- Маркеры, камера, мировые координаты — это делают клиенты примитивами библиотеки.
- Глобальные темы, файлы конфигурации, сохранение состояния между запусками.
- Docking и вынос панелей в отдельные окна ОС.

## 16. Проверка

- В облаке: проверка компиляции (clang-cl + заголовки Windows SDK).
- Запуск и визуальная проверка — на машине разработчика.

## 17. Порядок работы

1. Ядро, DX11, окно-хост, панели, layout, Label, Button, CheckBox, Slider.
2. Текст с glow, TextBox, ComboBox, Drag, векторы.
3. Tabs, ColorPicker, Image.
4. Шлифовка анимаций.
