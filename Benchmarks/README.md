# Бенчмарки: FunkyUI против Dear ImGui

Два консольных приложения с одним и тем же набором сцен:

- `FunkyBench` — FunkyUI (эта библиотека);
- `ImGuiBench` — Dear ImGui 1.92.9 (сабмодуль `third_party/imgui`) с бэкендами Win32 + DX11.

Всё общее — генератор сцен, цикл кадра, точки замеров, счётчики, статистика и отчёт — лежит в
`Common/BenchCommon.h`. Каждый бенчмарк только переводит нейтральную модель сцены в вызовы своей библиотеки.

## Сборка

```
git submodule update --init
```

Открыть `FunkyUI.sln`, конфигурация **Release | x64**, собрать `FunkyBench` и `ImGuiBench`.
Exe-файлы появятся в `bin\x64\Release\`. Debug-сборка работает, но её цифры ничего не значат (отчёт об этом
предупреждает).

## Запуск

Из консоли, по очереди (не одновременно):

```
bin\x64\Release\FunkyBench.exe
bin\x64\Release\ImGuiBench.exe
```

Появится окно 1280×720 DIP по центру основного монитора (при 150 % на 1080p это весь экран). Курсор мыши
переносится в центр окна — **мышь во время прогона не трогать**. `Esc` прерывает прогон, уже полученные
результаты всё равно попадут в отчёт. Полный прогон занимает несколько минут.

Параметры:

| Параметр | Что делает |
|---|---|
| `--scale F` | умножает количество всех объектов (по умолчанию 1) |
| `--frames N` | кадров замера на сцену (по умолчанию: Display 600, Throughput 1000) |
| `--warmup N` | кадров прогрева на сцену (по умолчанию 60, но не меньше 0,5 с) |
| `--layers N` | слоёв в эмуляции тени и glow у Dear ImGui (по умолчанию 8) |
| `--only Сцена` | только одна сцена (например `--only Effects`) |
| `--display-only` / `--throughput-only` | только один режим |
| `--quick` | вдвое меньше кадров замера |

Результаты: консоль и файл `<ИмяExe>_results.txt` рядом с exe — тот же текст плюс блок CSV
(строка на сцену и режим), удобный для сравнения в таблице.

Советы: закрыть лишние программы, ноутбук — от сети, одинаковые условия для обоих запусков;
прогнать по два раза и смотреть на повторяемость.

## Режимы

- **Display** — настоящее окно и vsync, как у оверлея. FunkyUI рисует оверлеем поверх окна бенчмарка
  (`Ui::Create`), ImGui — в свой flip-model swapchain этого окна с тем же пейсингом (max frame latency 1,
  ожидание waitable object, `Present(1, 0)`). FPS упирается в частоту монитора, поэтому сравнивать надо
  стоимость кадра (CPU, GPU), а не FPS.
- **Throughput** — своё устройство D3D11, offscreen-текстура размером с окно, без Present: очистка, отрисовка,
  event query и ожидание, пока GPU закончит кадр. FPS = 1000 / среднее время кадра (без генерации сцены) —
  реальная пропускная способность CPU + GPU, как при встраивании в чужой swapchain. FunkyUI работает через
  `Ui::CreateEmbedded`.

## Сцены (количества при `--scale 1`)

Всё движется или меняется каждый кадр, если не сказано иное. Координаты логические (1280×720 DIP).

| Сцена | Содержимое |
|---|---|
| Idle | меню (24 панели) + маленький фон (5 % от Background), всё неподвижно. Стоимость статичного UI: FunkyUI пропускает Present, если кадр не изменился, ImGui рисует всё заново |
| Menu | 24 панели шириной 280 каскадом по экрану: сетка 10 строк «Parameter NN» + слайдер, 6 чекбоксов, 3 кнопки, свой переключатель с анимированным ползунком. Слайдеры меняются каждый кадр, чекбоксы переключаются раз в ~40 кадров. UI в интерактивном режиме, курсор над панелями |
| Background | 2000 скруглённых прямоугольников с рамкой 1 px, 1000 кругов, 300 дуг, 1000 линий, 200 полилиний по 12 точек, 400 кривых Безье (толщина 2), 800 треугольников, 400 шестиугольников, 800 текстов (половина статичные, половина с числами, меняющимися каждый кадр) |
| Mixed | 12 панелей меню + Background с половинными количествами — реалистичный оверлей |
| TextStatic | 3000 коротких строк, текст не меняется, позиции плывут |
| TextDynamic | 3000 строк, числа в которых меняются каждый кадр (худший случай для кэша раскладок) |
| TextFonts | 3 шрифта (Segoe UI, Consolas, Arial) × 6 размеров (12–48) × 120 строк |
| Fill | 80 прямоугольников 480×320 (прозрачность 0,25, радиус 16) + 40 кругов r = 220 (0,2): много перекрытий, нагрузка на заливку |
| Effects | 600 прямоугольников с тенью (blur 12), glow 10 и градиентом, 200 кривых Безье с glow 8, 300 кругов с glow 12 |
| Ramp | только Throughput: движущиеся прямоугольники, круги, линии и тексты поровну, 1000, 2000, 4000 … до 256000 объектов, пока FPS не упадёт ниже 20. Итог — сколько объектов держится при 60, 144 Гц и частоте вашего монитора |

У ImGui нет теней, glow и градиентов на фигурах, поэтому они эмулируются обычным для ImGui способом:
тень — `--layers` расширяющихся полупрозрачных фигур, glow фигур — `--layers` контуров растущей толщины,
glow линий — 6 штрихов от широкого и бледного к узкому и яркому, градиент — перекраска вершин
(`ShadeVertsLinearColorGradientKeepAlpha`). В FunkyUI всё это нативно.

## Метрики

| Метрика | Смысл |
|---|---|
| FPS | кадров в секунду (в Display ограничено монитором). В Throughput — 1000 / среднее время кадра |
| Interval p50/p95/p99 | время между кадрами, мс; большой p99 — рывки. В Throughput — время кадра: от конца генерации сцены до готовности GPU (генерация не входит) |
| CPU Mcyc avg/p95 | мегациклы CPU потока рендера на кадр (`QueryThreadCycleTime`): весь цикл кадра, кроме генерации сцены, включая BeginFrame, обработку сообщений и Present. Ожидание vsync циклов не тратит, поэтому это честная цена кадра для CPU |
| CPU ms | то же в миллисекундах (частота счётчика циклов измеряется при старте) |
| Build | код UI: от конца BeginFrame/NewFrame до EndFrame/Render, мс avg/p95/p99 |
| Submit | EndFrame, либо Render + RenderDrawData + Present (в Throughput ещё Flush), мс |
| GPU wait | Throughput: сколько CPU ждал GPU после отправки кадра (в CPU Mcyc не входит) |
| Proc CPU % | Display: процессорное время всех потоков процесса (включая потоки драйвера и генерацию сцены) за весь цикл, % одного ядра |
| Other CPU % | Throughput и Ramp: то же без потока рендера — потоки драйвера и рантайма. Поток рендера там никогда не блокируется (крутится, пока GPU не закончит), поэтому с ним было бы всегда ~100 %; его цена — CPU Mcyc. Оба счётчика (`GetProcessTimes` / `GetThreadTimes`) идут шагом ~15,6 мс: на коротких замерах (быстрые шаги Ramp по 300 кадров — это ~0,1 с) шум ±15 % и больше |
| GPU %, GPU ms | загрузка 3D-движка GPU этим процессом (PDH) за весь цикл; GPU ms = загрузка × интервал кадра (только Display) |
| Headroom FPS | 1000 / max(CPU ms, GPU ms): сколько FPS позволила бы стоимость кадра без vsync |
| WS / Peak WS / Private / GPU MB | память процесса в конце сцены: рабочий набор, его пик, private bytes, видеопамять процесса («-» — недоступно). Накопительно: сцены идут в порядке таблицы |
| Vtx / Idx | вершины / индексы на кадр (только ImGui) |
| Items | примитивов + контролов в кадре |

Везде, кроме FPS и Headroom, меньше — лучше.

## Честность сравнения

- Содержимое кадра генерируется общим кодом только из номера кадра (без времени) и до измеряемой части кадра:
  обе библиотеки получают побитово одинаковые данные. В Throughput генерация не входит ни во время кадра, ни в FPS,
  ни в итоги Ramp. В Display интервал меряется от кадра до кадра, и генерация прячется в ожидании vsync.
- Одинаковые точки замеров, одинаковый прогрев (N кадров и не меньше 0,5 с), одинаковый пейсинг
  (max frame latency 1 + waitable object), один формат B8G8R8A8, один DPI и размер цели.
- Курсор в одной и той же точке: в Display — реальный курсор (обе библиотеки опрашивают его каждый кадр),
  в Throughput — передаётся явно.
- Размеры шрифтов в сценах — em в DIP, как у DirectWrite (FunkyUI). У Dear ImGui размер шрифта — это высота
  ascent − descent из таблицы hhea, поэтому ImGuiBench пересчитывает размеры по метрикам каждого шрифта
  (у Segoe UI em 14 DIP — это размер ImGui ≈ 18,6): глифы у обеих одного размера. Шрифт по умолчанию у обеих —
  Segoe UI, em 14 DIP; стиль — родной тёмный каждой библиотеки.
- Исходники Dear ImGui компилируются с теми же флагами кодогенерации, что библиотека FunkyUI (`/O2 /fp:fast /GS-`);
  код самих бенчмарков — с одинаковыми флагами по умолчанию.
- Композиция окон идёт в процессе dwm.exe и не входит ни в чьи цифры, а у двух библиотек она разная: оверлей
  FunkyUI — отдельное окно с прозрачной поверхностью DirectComposition, которую DWM при каждом обновлении
  смешивает поверх окна бенчмарка, а ImGui рисует прямо в swapchain окна. Эта доля работы GPU в Display
  у FunkyUI не видна; её можно сравнить в Диспетчере задач (Подробности → dwm.exe → столбец «GPU») во время
  прогонов обеих.
